System Architecture Specification

Architecture
  • Filter Layer: CORS, Security Headers (nosniff, DENY, XSS protection), Session Check (AuthFilter).
  • Controller Layer: Thin HTTP routing and JSON serialization; zero business rules or raw database queries.
  • Service Layer: Pure C++ business logic, bounds validation, and transactional orchestration.
  • Repository Layer: 100% parameterized SQL; abstracts relational storage behind polymorphic C++ interfaces.
  • Persistent Storage: Embedded SQLite 3 with WAL mode for zero-configuration testing; PostgreSQL 15+ production readiness.

AI Guardrails & Reliability Hardening

AI Guardrails
  • Per-Session Rate Limiting: Enforces strict ceiling of 10 messages per minute per session ID via a thread-safe mutex window (HTTP 429).
  • Deduplication In-Memory Cache: Repeated questions in a session return instant cached replies (cached = true) in 0ms.
  • Fixed Server-Side Prompt Template: Restricts AI scope strictly to marketplace products, shipping, returns, and seller onboarding.
  • Degraded Fallback Resilience: Outbound calls feature 5-second timeouts; network dropouts gracefully degrade to canned domain knowledge.

7 Required Design Patterns (Section 10)

Design Patterns
  • 1. Repository Pattern: Abstract SQL interfaces (IUserRepository, IProductRepository, etc.).
  • 2. Front Controller Pattern: Centralized HTTP routing, session extraction, and security headers.
  • 3. Singleton Pattern: Thread-safe SessionManager::Instance() for session tokens.
  • 4. Factory Pattern: ChatProviderFactory for polymorphic AI providers.
  • 5. Strategy Pattern: Swappable AI implementations behind ChatProvider.
  • 6. Builder Pattern: Fluent DTO constructors ensuring password hashes never leak.
  • 7. Dependency Injection: Manual constructor injection across all services.

Security & Hardening Checklist

Security
  • 100% Parameterized SQL: All queries use prepared statements and parameter binding.
  • Argon2id Hashing: Passwords securely hashed with Argon2id via libsodium.
  • Session Fixation Defense: Pre-authentication sessions destroyed; fresh tokens issued upon login.
  • Zero Error Leakage: Universal exception handler standardizes all errors without exposing traces.
  • Memory Safety: Zero raw owning pointers; 100% managed via unique_ptr and shared_ptr.
